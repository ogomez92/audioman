# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Windowless Windows tray-less utility that lets a user adjust per-application audio session volume, route individual apps to specific input/output devices, and manage endpoint devices (volume, mute, enable/disable) via global hotkeys, with feedback spoken through whichever screen reader / TTS backend is active. Inspired by an NVDA add-on (Python) at `C:\Users\Nitropc\Downloads\audiomanager` — the Rust port deliberately drops NVDA-specific pieces (microphone lock timer, NVDA output-device nav).

## Build / run

```
cargo build            # debug
cargo build --release  # release, strips symbols + LTO
cargo run              # runs debug exe — headless, speaks "Audio manager ready"
```

Hotkeys (all use `Ctrl+Win+Alt` as the base modifier, registered with `MOD_NOREPEAT`). `0` toggles between **application mode** (default) and **device mode**; the other keys act on whatever the mode targets:

- 0 — toggle application mode / device mode
- Shift+0 — app mode: open the "Applications to show" checklist; unchecked apps are skipped by Left/Right (persisted by process name in `%APPDATA%\audioman\hidden.txt`). Device mode: the same checklist as "Devices to show"; unchecked devices are skipped by Left/Right (persisted by endpoint id + name in `%APPDATA%\audioman\hidden_devices.txt`, so an unplugged hidden device stays listed and can be unhidden)
- Left / Right — previous / next audio session (app mode) or audio device (device mode; outputs first, then inputs, including disabled devices; announces name, direction, enabled/disabled, mute, volume)
- Up / Down — volume ±2% (session or endpoint master volume by mode)
- PageUp / PageDown — volume +20% / -20%
- Home / End — set volume to 0% / 100%
- M — toggle mute (session or endpoint by mode)
- Backspace — restore every session to 100% and unmute (both modes)
- Enter — app mode: open the device picker to route **the selected app's** audio (input and output) to chosen devices; device mode: enable/disable the selected device
- Shift+Enter — toggle **output duplication**: opens a dialog (source output, target output, latency profile) and starts mirroring everything playing on the source onto the target; pressing it again stops. Source preselects the device selected in device mode (else the default output); target and latency preselect the last-used values (`%APPDATA%\audioman\mirror.txt`). The wanted duplication is saved to `%APPDATA%\audioman\active_mirror.txt` (source id, target id, latency, source name, target name). Whenever it is wanted but not running (at startup, after a device is unplugged, after an engine failure) it is retried every 5 s and on every device change, and resumes as soon as both devices are active outputs. Shift+Enter while it is waiting cancels it. Only Shift+Enter clears the file — quitting, a runtime failure or a missing device keeps it
- Shift+S — toggle **streaming to a SonicRoom room**: opens a dialog (server or room link, room, name in the room, device, channels, quality) and streams the chosen device (an output via loopback, or an input) into the room as a send-only caster; pressing it again stops. Device preselects the device selected in device mode (else the last one streamed, else the default output); everything else preselects the last-used values (`%APPDATA%\audioman\sonicroom.txt`, saved even when the dialog's input is rejected). Once the stream first goes live it is saved to `%APPDATA%\audioman\active_sonicroom.txt` and, exactly like duplication, retried every 5 s and on every device change whenever it isn't running (startup, lost connection, server restart, device unplugged). A stream that never went live (wrong server, room refused) is dropped instead of retried. Shift+S while it is waiting cancels it. Shift+S clears the file, and so does someone in the room removing the caster (SonicRoom's "Remove caster" is meant to keep it gone); quitting, a lost connection or a missing device keep it
- Q — quit

The app has no window and no console (`#![windows_subsystem = "windows"]`). Kill via the Quit hotkey or Task Manager.

## Architecture

Sixteen modules, one binary:

- **`src/main.rs`** — owns the Win32 message loop and the `Mode` (apps vs devices) state. Registers hotkeys against `HWND(null)` so `WM_HOTKEY` posts to the thread queue. Session volume ops funnel through `apply_volume()`, endpoint volume ops through `apply_device_volume()` — both take a closure over the current volume. Device-mode navigation (`DeviceNav`) re-enumerates on every Left/Right press and keeps selection by endpoint id. The loop also handles `audio::WM_DEVICES_CHANGED` (thread message, `WM_APP + 1`): it drains duplicate messages with `PeekMessageW` and calls `AudioManager::rebuild()`. After the picker closes it rebuilds unconditionally — thread messages posted while the dialog's nested loop ran are dropped.
- **`src/audio.rs`** — WASAPI session tracking across **all active render endpoints** (one `IAudioSessionManager2` + `IAudioSessionNotification` per device), not just the default — with per-app routing an app can live on any endpoint. An `IMMNotificationClient` posts `WM_DEVICES_CHANGED` to the main thread on any device add/remove/state/default change; the main thread responds with `rebuild()` (detach everything, re-enumerate, restore selection by pid then name). `add_session` **replaces** an existing same-pid session instead of skipping: when an app moves endpoints the new session appears before the old one expires, and skip-dedup would drop the app entirely when the old session died. Never call `UnregisterAudioSessionNotification` from inside a WASAPI callback (deadlock risk) — callback-path removals just drop refs; explicit unregistration happens only in `detach_all()` on the main thread. Process name comes from `QueryFullProcessImageNameW` with `PROCESS_QUERY_LIMITED_INFORMATION` (deliberately not `GetModuleBaseNameW` — the latter needs `PROCESS_VM_READ` and fails on protected processes). `pid == 0` identifies the system-sounds session; **do not** rely on `IsSystemSoundsSession().is_ok()` for that check — the method returns `S_OK`/`S_FALSE` (both COM-success) and `windows-rs` collapses both to `Ok(())`, so every session looks like system sounds.
- **`src/hidden.rs`** / **`src/apps_dialog.rs`** — app visibility. `State.hidden` holds process names (case-insensitive); hidden sessions stay in `State.sessions` (so the dialog can list them and Backspace still restores them) and are filtered only by `State::visible_indices()` in `navigate()` and selection restore in `rebuild()`. The dialog is a `SysListView32` with `LVS_EX_CHECKBOXES` (checked = shown), reusing `dialog.rs`'s label/button helpers and the same Enter/Esc modal-loop pattern; it lists running apps plus remembered hidden ones that aren't running. `apps_dialog::show_devices` reuses the same window for device mode; `DeviceNav.hidden` (endpoint ids) is filtered by `DeviceNav::visible_indices()` in `navigate_devices()` and `select_initial()`, while `nav.devices` keeps every endpoint so the dialog can list hidden ones.
- **`src/routing.rs`** — per-app device routing via the undocumented `Windows.Media.Internal.AudioPolicyConfig` WinRT class (what Settings → App volume and device preferences uses). `SetPersistedDefaultAudioEndpoint(pid, flow, role, path)` persists by app identity (survives restarts/reboots); a null HSTRING clears it. The endpoint argument is `\\?\SWD#MMDEVAPI#<id>#{DEVINTERFACE_AUDIO_RENDER-or-CAPTURE}`, not a bare MMDevice id. The factory IID changed at Win10 build 21390 (layout identical) — current IID first, then raw-QI fallback to the old one. The interface is IInspectable-based: 3 IInspectable methods + 19 stub slots precede the real methods — **do not reorder or remove them**. Set/get fail with `E_INVALIDARG` for pids without a live audio session, so only pass pids taken from enumerated sessions. Sets console + multimedia roles (matches Windows Settings).
- **`src/prism.rs`** — minimal FFI for prism TTS (header bundled at `vendor/prism/prism.h`). `Speaker::new` does `prism_init` → `prism_registry_acquire_best` → `prism_backend_initialize`. `acquire_best` does *not* transfer ownership — `prism_shutdown(ctx)` cleans up acquired backends; do **not** call `prism_backend_free` on it. Auto-selects NVDA / JAWS / SAPI / whatever's running.
- **`src/devices.rs`** — endpoint enumeration (`IMMDeviceEnumerator::EnumAudioEndpoints`; friendly name via `IPropertyStore` + `PKEY_Device_FriendlyName`), endpoint master volume/mute (`IAudioEndpointVolume`), default-device switching, and endpoint enable/disable. `all_endpoints()` enumerates `ACTIVE | DISABLED` so disabled devices stay reachable for re-enabling; `inputs()`/`outputs()` (used by the picker) stay active-only. Default switching and visibility have **no** public API — both go through the undocumented `IPolicyConfig` interface on `CPolicyConfigClient`, declared with `#[interface]`. Only `SetDefaultEndpoint` and `SetEndpointVisibility` are called; the earlier vtable slots are stubs that exist only to land them at the right offsets, so **do not reorder or remove them**. `set_default` sets all three roles (console / multimedia / communications).
- **`src/mirror.rs`** — output duplication. A worker thread (MTA COM, MMCSS "Pro Audio") runs three WASAPI streams: a shared-mode **loopback capture** on the source, a **silent render stream on the source** whose event is the capture clock (loopback streams never signal on their own; Windows only delivers loopback data in step with a render stream on the same endpoint), and an event-driven **render stream on the target**. Each stream is opened through `IAudioClient3::InitializeSharedAudioStream` at the engine's minimum period (`Latency::Lowest`) or default period, falling back to classic `Initialize` when the driver refuses; most USB headsets report min = default = 10 ms, so "lowest" often lands at 10 ms periods anyway. All three streams use the **source mix format**; if the target's mix format differs the target stream adds `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY` and the engine converts. Frames pass through a `VecDeque<u8>` ring with a cushion (`Latency` picks half/one/three period-sums): above the high-water mark the ring is trimmed (source clock ahead), on underrun silence is padded and the cushion rebuilt. Runtime failures post `WM_MIRROR_STOPPED` (`WM_APP + 2`) to the main thread. `main.rs`'s `Duplication` keeps the wanted duplication (`mirror::Active`) apart from the running engine: a stop drops the `Mirror` and speaks `Mirror::failure()`, and `Duplication::try_resume` (5 s thread timer from `SetTimer(HWND(null))`, plus every `WM_DEVICES_CHANGED`) restarts it. Stops are detected by `Mirror::failure()` being set, not by the message alone: the message is lost if it arrives during a dialog's nested loop, and a late one must not kill a freshly resumed engine. Start errors during retries are spoken only from the second consecutive failure (a just-plugged device often refuses once) and only once per distinct error. `Mirror::start` blocks until both devices are open so errors are spoken synchronously; `Drop` signals a stop event and joins. `Stats` exposes periods, cushion and glitch counters; `estimated_delay_ms()` is what the start announcement quotes. `audio::add_session` skips sessions owned by our own pid so the engine's two render streams never show up as an "audioman" app. A `#[test]` smoke-tests the engine between the first two active outputs on the machine (`AUDIOMAN_MIRROR_TEST_MS` sets the run length).
- **`src/wasapi.rs`** — WASAPI helpers shared by the two real-time engines (`mirror.rs`, `caster.rs`): owned `Format` copies (mix format, or a synthesized 48 kHz float format), `open_stream` (event-driven, `IAudioClient3` minimum/default period with classic `Initialize` fallback, render or capture), `fill_silence`, and `describe` for spoken error wording.
- **`src/caster.rs`** — streaming a device into a SonicRoom room (the `sonicroom/` checkout is the server/web client; it is a separate repo, not part of this build). SonicRoom accepts send-only **casters** (`join` with `role: "caster"`): no knock gate, not counted as people, one producer announced to everyone. We always produce `source: "music"` (stereo-capable, the Ecobox contract, removable via "Remove caster"; it is ducked while people talk like any music) with the device name as `title`. One worker thread (MTA COM, MMCSS) does everything: capture (output → loopback clocked by a silent render stream, same trick as `mirror.rs`; input → event-driven capture; both at the engine minimum period; mix format used directly when it is 48 kHz float with ≤ 2 channels, else `AUTOCONVERTPCM` to 48 kHz float stereo), Opus encode (`opus.rs`), WebRTC via **str0m** (sans-IO; DTLS through Windows CNG, `wincrypto` feature) over one UDP socket, and signaling via `socketio.rs`. It waits on the stop event, the capture event and a `WSAEventSelect` read event for the socket at once, so a packet leaves as soon as its last sample is captured. str0m's contract is mutate → drain `poll_output` to `Timeout` → mutate; `Session::drain` is that drain. Setup: `join` → `create-transport` → str0m offer (`mediasoup::parse_offer`) / fabricated answer (`mediasoup::answer`, IPv4 candidates only) → `connect-transport` (we are DTLS client) → `produce`; ICE/DTLS then complete inside the loop (`Event::Connected` = `Phase::Live`). `Quality` = packet size + Opus mode (5 / 10 / 20 ms; restricted-low-delay CELT for the first two). `Channels::Auto` = stereo for outputs, mono for inputs. `Caster::start` blocks only until the device is open; connecting reports through `Phase` (`Connecting`/`Live`/`Failed`/`Removed`), each change posting `WM_CASTER_CHANGED` (`WM_APP + 3`). A server `41` (namespace disconnect) means a participant removed the caster → `Removed`; the media path usually dies a few ms before the `41` arrives, so `removed_by_server()` checks signaling before calling it a failure. `main.rs`'s `Casting` mirrors `Duplication` (wanted vs running, 5 s retries, speak a retry error only from the second failure and once per distinct error) plus a `proven` flag (never live → drop, don't retry). Errors are spoken, so keep them plain words, never raw OS/library text. Tests: `streams_into_a_room` and `removed_by_the_room` run against a real server when `AUDIOMAN_SONICROOM_TEST_SERVER` is set (e.g. `http://localhost:3100`; run the server with `ANNOUNCED_IP` set to the LAN address, since Chrome won't pair with a `127.0.0.1` candidate), asserting the SFU's RTCP receiver reports saw the packets.
- **`src/caster_dialog.rs`** — the Shift+S dialog: three `EDIT`s (`dialog.rs`'s `make_edit`, label-then-edit like the combos) and three combos; focus lands on the first empty field, else the device. A pasted room link (`…/room/<name>`) fills an empty room.
- **`src/mediasoup.rs`** — pure helpers for mediasoup's send-transport handshake without mediasoup-client: read `create-transport` params, read str0m's offer (mid, payload type, ssrc, cname, mid extension id, our fingerprint), fabricate the server's ICE-lite answer (`setup:passive`), and build `produce` RTP parameters. Opus is always `opus/48000/2` (mediasoup matches the router's channel count); mono/stereo travels in `stereo`/`sprop-stereo`, which listeners' browsers need to decode stereo at all. Unit-tested, including that str0m parses the fabricated answer.
- **`src/socketio.rs`** — minimal Socket.IO v4 client over a `tungstenite` WebSocket (TLS via native-tls/SChannel): Engine.IO open, `40` connect, `42`/`43` emit with ack, ping/pong, `41` = `Closed::ByServer`. Non-blocking after connect so the caster loop can `poll()` it between audio ticks. `websocket_url` accepts `host`, `https://host` or a full room link.
- **`src/opus.rs`** — safe wrapper over `unsafe-libopus` (libopus transpiled to Rust, so the build still needs no C toolchain; `Cargo.toml` builds it at `opt-level = 3` even in dev, it is too slow for real time otherwise).
- **`src/mirror_dialog.rs`** — the Shift+Enter dialog: three combos (Duplicate from / Duplicate to / Latency) built with `dialog.rs`'s `make_combo`, plain lists with no synthetic "Default" entry, focus lands on the target combo. Returns indices into the `outputs` slice; main rejects source == target.
- **`src/dialog.rs`** — the Enter-hotkey device picker, built from raw Win32 controls (`COMBOBOX` + `BUTTON` + `STATIC`) so it inherits native MSAA/UIA accessibility for NVDA/JAWS/Narrator. Each combo is named by the `STATIC` label created immediately before it (z-order label-association heuristic — **keep label-then-combo creation order**). Each combo's first item is a synthetic **"Default"** entry — real devices follow at combo index 1+, so device N sits at index N+1. The dialog is per-app: the title names the selected app, the caller preselects the app's current routing, and accepting returns a `Choice` per direction — `Default` means "follow the system default" (main clears the per-app assignment). For the pid-0 system-sounds session (no process to route), main falls back to switching the **system** default devices. It's a normal registered-class window (not a real dialog), so keyboard behavior is supplied manually: `IsDialogMessageW` for Tab/Shift+Tab, plus explicit Enter = accept / Esc = cancel that defers to an open combo dropdown via `CB_GETDROPPEDSTATE`. That loop (`run_modal`), the window proc (`modal_wndproc`) and the heap-allocated `ModalState` (pointer in `GWLP_USERDATA`) are shared by all four dialogs (`dialog.rs`, `apps_dialog.rs`, `mirror_dialog.rs`, `caster_dialog.rs`), as are `fill_combo` / `selected_index` / `make_edit` / `window_text`. Runs nested on the main thread. The screen reader narrates the controls natively, so the dialog itself does **not** drive prism — main speaks only the post-accept confirmation.

## Linking prism

prism is **vendored in-repo** at `vendor/prism/` (`prism.lib` — the x64 dynamic import library, `prism.dll`, and `prism.h`) so a fresh clone builds with no external SDK. `build.rs` resolves that directory via `CARGO_MANIFEST_DIR`, links `prism.lib`, and copies `prism.dll` next to the built exe on each build. The DLL must sit next to `audioman.exe` at runtime (`install.ps1` carries it across). To update prism, drop new files into `vendor/prism/` — they came from the SDK's `prism-windows-x64/{dynamic/release/lib,dynamic/release/bin,include}`. `build.rs` also declares `rerun-if-env-changed=CARGO_MANIFEST_DIR`: the link-search path is absolute, and without it a moved checkout keeps linking against the old location's cached path (LNK1181).

## Threading / COM

Main thread calls `CoInitializeEx(COINIT_APARTMENTTHREADED)` once at startup; `RoGetActivationFactory` (routing) rides on that same init. All WASAPI / session enumeration runs on that thread. The worker threads are the two engines — the mirror (`mirror.rs`) and the room stream (`caster.rs`) — each of which initializes its own MTA COM and creates every COM object it uses itself; the main thread only hands them endpoint ids, settings and a stop event. Don't introduce other worker threads for audio work without also initializing COM on them. WASAPI/MMDevice **callbacks** (`IAudioSessionNotification`, `IAudioSessionEvents`, `IMMNotificationClient`) arrive on WASAPI worker threads — they only touch the `Arc<Mutex<State>>` or `PostThreadMessageW`; keep COM object creation out of them.
